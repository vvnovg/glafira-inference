# Glafira for LLM Inference

Desktop-приложение (Tauri 2 + Rust + React) для подключения к корпоративному инференсу open-source LLM, его
мониторинга, диагностики и аудита; в фокусе — vLLM и SGLang на GPU NVIDIA.

Состояние: готовы этапы I1a и I1b — подключение, проверка и метрики сервера. Это инсталляции из серверов, определение
типа, версии и моделей сервера, пошаговая проверка сервера, папки, экспорт и импорт, а также вкладка сервера: плитки и
графики метрик «сейчас» (опрос `/metrics` раз в 5 с) и аргументы запуска с источниками. История метрик, GPU,
диагностика и аудит появятся в следующих этапах, I1c–I7 (спецификация, §20).

vLLM, SGLang, LiteLLM, NVIDIA and other product names are trademarks of their respective owners. This project is not
affiliated with them.

Спецификация: `docs/superpowers/specs/2026-10-29-glafira-inference-design.md`. Код, общий с Glafira for Kubernetes
(а через неё — с Glafira for Apache Kafka), перечислен в `PORTED.md`.

## Установка

Установщики для macOS (`.dmg`, `.pkg`), Windows (`.msi`) и Linux (`.deb`, `.rpm`, `.AppImage`):
https://github.com/vvnovg/glafira-inference-releases/releases

Приложение для macOS (`.dmg`) подписано и нотаризовано. `.pkg` для Jamf и Intune пока не подписан: при первом
открытии разрешите его в «Системных настройках» → «Конфиденциальность и безопасность» → «Всё равно открыть». Сборки для Windows пока не подписаны: если SmartScreen блокирует
установщик, выберите «Подробнее», затем «Выполнить в любом случае». Новые версии приложение находит само:
«О программе» → «Обновления».

## Релиз

Релиз собирает `.github/workflows/release.yml` по тегу `vX.Y.Z`. Он выпускает подписанные установщики для трёх ОС
и `latest.json` для обновлений внутри приложения и публикует их в `vvnovg/glafira-inference-releases`. Подготовка
версии, секреты, пробный прогон и смоук установщиков описаны в `docs/release-checklist.md`.

## Требования
- Rust stable (`rustup`), Xcode Command Line Tools (macOS)
- Node 22+, pnpm 11
- GPU не нужен: для разработки и смоука есть мок-сервер (`pnpm mock-server`, ниже)

## Запуск
```bash
pnpm install
pnpm tauri dev
```
Dev-сервер Vite слушает порт 1440 (1420 и 1430 заняты Kafka- и Kubernetes-версиями), приложения семейства можно
запускать рядом.

## Мок-сервер
`pnpm mock-server --kind <вид> [--port 8000] [--host 127.0.0.1] [--api-key sk-dev] [--health 200..599] [--models full|empty]
[--engines 1..8] [--reset-after N]` отвечает как сервер инференса снимками ответов из `src-tauri/src/servers/testdata` —
теми же, что проверяют тесты Rust. Виды: `vllm` (0.32, настоящий снимок), `vllm-0.11`, `vllm-0.10` (старые и новые имена
метрик рядом, два движка), `vllm-0.8` (модель с адаптером LoRA; ниже границы поддержки), `vllm-old` (0.7), `sglang`
(0.5.22), `sglang-no-metrics` (0.5.22 без `/metrics`, как без `--enable-metrics`), `sglang-0.5.4`, `sglang-0.4` (устаревшие пути `/get_*`, без метрик; ниже границы), `llamacpp`, `ollama`
(без `/health`).
- `/metrics` видов `vllm`, `vllm-0.10` и `sglang` «живой»: счётчики и гистограммы растут с каждым опросом, KV-кэш
  колеблется. `--engines N` — N движков data parallel, `--reset-after N` — после N опросов счётчики начинаются заново,
  как при перезапуске сервера.
- Если задан `--api-key`, ключ (`Authorization: Bearer <ключ>`) нужен не всем путям. У vLLM, llama.cpp и Ollama — только
  `/v1*`, остальное открыто. У SGLang без ключа открыты только `/health*` и `/metrics*`.
- `--health` — код ответа `/health`; у 3xx есть заголовок `Location` на `https://…/health`.
- `--models empty` отдаёт пустой список моделей, `--models full` (по умолчанию) — снимок.
- `--port 0` занимает любой свободный порт.

## Инсталляции и серверы
- Инсталляция — серверы инференса одной системы (`storage/profile.rs`): имя, окружение, только чтение, таймауты и
  серверы. Сервер — имя, адрес (`http://` или `https://`, путь допускается; `user:pass@` запрещён), тип (`auto`,
  `vllm`, `sglang`, `openai`), путь метрик, CA (системные корни, только перечисленные PEM, без проверки) и прокси.
  Не больше 32 серверов; id сервера генерирует форма, он входит в ключ keychain.
- Клиент сервера (`servers/client.rs`): только GET, перенаправления не выполняются (ключ API не уходит на другой адрес),
  ключ — `Authorization: Bearer` с пометкой «чувствительный», лимит тела — 1 МБ для JSON, 8 МБ для метрик.
- Определение типа (`servers/detect.rs`, чистые функции над снимком ответов): SGLang — `/model_info` и `/server_info`
  (у старых версий — `/get_model_info`, `/get_server_info`), префикс `sglang:` в метриках или `owned_by: sglang`;
  vLLM — префикс `vllm:`, `owned_by: vllm` или JSON `/version` (его хватает, только если список моделей не пуст и ни у
  одной модели нет `owned_by`: обратный прокси мог вырезать это поле; пустой список признаком не служит); иначе
  `openai`. Тип из профиля побеждает признаки, но расхождение — предупреждение. vLLM ниже 0.8 и SGLang ниже 0.4
  работают как `openai` с предупреждением. Из `/server_info` берётся только версия: в ответе SGLang бывает ключ API.
- Подключение инсталляции (`servers/pool.rs`, `AppState::connected`): все серверы параллельно, ошибка сервера — в его
  состоянии; подключения одной инсталляции идут по очереди. Сохранение профиля, удаление и импорт забывают подключение.
- Проверка сервера (`servers/connectivity.rs`): конфигурация → DNS/TCP → TLS (только `https://`; при выключенной
  проверке сертификата шаг пишет «сертификат не проверяется») → `/health` → вход (`/v1/models` с ключом) → тип и
  версия → модели. Предупреждения успеха не отменяют.
  - TCP идёт к серверу, а если в профиле прокси задан явным адресом — до самого прокси. Системный прокси — это
    переменные `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` (исключения — в `NO_PROXY`), а на macOS и Windows ещё и
    настройки ОС: если он покрывает адрес сервера, TCP не проверяется (шаг сообщает, что используется системный прокси),
    соединение проверят следующие запросы.
  - `/health`: 404 — пропуск, 401/403 — проверит шаг «Вход», 3xx — ошибка перенаправления («укажите конечный адрес»),
    прочие 4xx — неожиданный статус; «не готов» бывает только при 5xx.

## Где хранятся данные
- Профили и папки: `installations.json` в каталоге данных (macOS:
  `~/Library/Application Support/io.github.vvnovg.glafira.inference/`), права 0600.
- Ключи API — в системном хранилище секретов, сервис `glafira-inference`, ключ `<id инсталляции>/<id сервера>/apiKey`.
- Настройки: `settings.json`.
- Экспорт — файл `*.glafira-inference-installations.json` без ключей API; у каждой инсталляции — список серверов, чей
  ключ был сохранён (`needsSecret.apiKeys`). Импорт с «Обновлять существующие» предупреждает, если у сервера с
  сохранённым ключом меняется адрес, прокси или проверка сертификата; ключи серверов, которых нет в файле, удаляются.
- Логи: `RUST_LOG=debug pnpm tauri dev`; файлы — в папке логов ОС (путь — в «О программе»).
