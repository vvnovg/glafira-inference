# Glafira for LLM Inference — спека этапа I1d «GPU»

Уточнения поверх общей спеки `docs/superpowers/specs/2026-10-29-glafira-inference-design.md` (дальше — «общая
спека») и спек I1b и I1c (`2026-10-31-glafira-inference-i1b-design.md`, `2026-10-31-glafira-inference-i1c-design.md`).
Где эта спека молчит, действуют они. Решения брейншторма 2026-11-01.

## 1. Решения и границы

- **Проверка — на моках.** Стенда с GPU NVIDIA нет, на Mac dcgm-exporter не запускается. Мок `mock-server.mjs`
  отдаёт `/metrics` в формате dcgm-exporter 4.8.4, собранном по его исходникам (`etc/default-counters.csv`,
  `internal/pkg/rendermetrics/render_metrics.go`); локальный Prometheus смоука опрашивает моки DCGM, так проверяются
  оба режима. Пункты смоука для стенда с GPU отложены до стенда, как в I1b и I1c.
- **Режимы источника — `direct` и `prometheus`** (§5.3 общей спеки). Режим `ssh` (`nvidia-smi` по SSH) и процессы
  на карте — I3.
- **Простая привязка сервера к GPU — уже в I1d** (раздел 2): хост и номера карт в профиле сервера, автоподбор по
  хосту URL. В I3 это поле войдёт в связи компонентов (§5.7 общей спеки) и будет заполняться точнее.
- **Карты инсталляции в режиме `prometheus` ограничивает селектор GPU** с автоподбором по хостам серверов; не
  больше 64 карт на инсталляцию.
- **Время на экране GPU — как у сервера:** окно «Сейчас» (опрос раз в 5 с) и окна 1 ч / 24 ч / 7 д / 30 д из
  источника истории в обоих режимах; в `direct` экспортёр сопоставляется с целью Prometheus.
- **Подход A, как в I1b и I1c:** опрашивает фронтенд, пока вкладка видна; разбор, приросты и PromQL — в Rust.
- **Не входит в I1d:** режим `ssh` и процессы на карте (I3); правила `gpu.*` и MCP `get_gpu_status`,
  `get_metrics_history` для GPU (I2); метрики экземпляров MIG (после MVP).

**Что умеет dcgm-exporter 4.8.4** (по исходникам, ветка `main` на 2026-11-01). Метки карты: `gpu` (номер), `UUID`
(или `uuid` — по флагу экспортёра), `pci_bus_id`, `device`, `modelName`, `hostname` (до 4.1 включительно — `Hostname`), у MIG —
`GPU_I_PROFILE`, `GPU_I_ID`; версия драйвера — меткой `DCGM_FI_DRIVER_VERSION`; в Kubernetes — `pod`, `namespace`,
`container`. Набор счётчиков по умолчанию (`default-counters.csv`) **не содержит** `DCGM_FI_PROF_SM_ACTIVE`, ECC
(`DCGM_FI_DEV_ECC_*`), причин троттлинга (`DCGM_FI_DEV_CLOCKS_EVENT_REASONS`), счётчиков `*_VIOLATION` и ошибок
NVLink; содержит `DCGM_FI_PROF_GR_ENGINE_ACTIVE`, `DCGM_FI_DEV_XID_ERRORS` (код последней ошибки, не счётчик),
remapped rows и `DCGM_FI_DEV_PCIE_REPLAY_COUNTER`. Поэтому у каждого поля — запасные серии, а отсутствие —
«нет данных» с подсказкой, какие счётчики включить.

## 2. Профиль, секрет, привязка

- `InstallationProfile.gpu: Option<GpuSource>` — не больше одного компонента GPU на инсталляцию:

  ```
  GpuSource {
    mode: direct {
            exporters: [{ url, historySelector? }],     // 1..16
            auth: none | basic { username },
            ca: CaConfig, proxy: ProxyConfig
          }
        | prometheus { selector? }                      // клиент, вход, CA и прокси — источника истории
  }
  ```

  Поля из более новой версии — `extra`, как у прочих частей профиля.
- `direct`: адрес экспортёра — `http(s)://host:port[/путь]`, путь по умолчанию — `/metrics` (нормализация дописывает
  его к адресу без пути); `user:pass@` в URL отклоняется (`errors.installations.credentialsInUrl`); без экспортёров —
  `errors.gpu.noExporters`, больше 16 — `errors.gpu.tooManyExporters`;
  повторяющийся адрес — `errors.gpu.duplicateExporter`. Без проверки сертификата — `CaConfig::Insecure` с постоянным
  предупреждением, запрещается политикой `allowInsecureTls = false` (при сохранении и импорте). Перенаправления не
  выполняются, как у серверов.
- `historySelector` экспортёра — селектор его серий в источнике истории, `{job="dcgm", instance="10.0.0.5:9400"}`;
  заполняет автоподбор (раздел 3) или человек; `None` — окна истории карт этого экспортёра недоступны.
- `prometheus`: без источника истории компонент не сохраняется (`errors.gpu.noHistorySource`); убранный источник
  истории убирает и такой компонент GPU (форма предупреждает до сохранения). `selector` — матчеры меток DCGM,
  разбор — тот же строгий разбор, что у селектора истории (I1c §3), `__name__` запрещён.
- **Секрет:** пароль basic — только в keychain, одной записью `gpu_secret_key(installationId)` =
  `<инсталляция>/gpu/secret`, общий для всех экспортёров. Правила — как у секрета истории (I1c §2): сохранённый
  остаётся, только пока не меняется вид входа; убранный компонент, вход «без входа», режим `prometheus` и удаление
  инсталляции удаляют секрет.
- **Привязка сервера:** `ServerConfig.gpus: Option<GpuBinding>`:

  ```
  GpuBinding { host, indices?: [u32] }   // indices = None — все карты хоста
  ```

  Подобранную проверкой привязку помнит форма, как селекторы истории в I1c: если после автоподбора у сервера меняется
  адрес, она сбрасывается, и следующая проверка подбирает заново; выбранная человеком остаётся. Нормализация:
  хост без пробелов, номера по возрастанию без повторов, пустой список — все карты; без компонента GPU привязок нет.
  Привязка с пустым хостом — `errors.gpu.badBinding`.
- **Экспорт и импорт** — как в I1c: секрета в файле нет, у инсталляции флаг `needsSecret.gpu`; при обновлении импорт
  предупреждает, если у компонента с сохранённым секретом меняются адреса экспортёров, прокси или проверка
  сертификата; без компонента в файле или с другим видом входа сохранённый секрет удаляется. Селекторы и привязки
  экспортируются как есть.

**Хост карты.** Метка `hostname` (dcgm-exporter 4.8), затем `Hostname` (4.1 и раньше); нет обеих — хост из URL экспортёра (`direct`) или из метки
`instance` без порта (`prometheus`). Карта — пара «хост + `gpu`»; `UUID` показывается в подсказке. Две карты с
одной парой (два экспортёра на одном хосте) — обе показываются, вторая с подписью экспортёра, проверка пишет ⚠️.

## 3. Проверка компонента и автоподбор

**Шаги проверки** (§5.8 общей спеки, уточнение):

- `direct`, на каждый экспортёр:
  1. DNS/TCP → TLS — как у серверов;
  2. `/metrics`: 401/403 — ❌ `errors.gpu.unauthorized` «Экспортёр DCGM отклонил запрос (401) — проверьте имя
     пользователя и пароль» на шаге `auth`; прочие не 2xx — ❌ статус; больше 8 МБ — `errors.metrics.tooLarge`;
  3. есть `DCGM_FI_DEV_FB_USED` (серия набора по умолчанию, есть и в режиме MIG, где `GPU_UTIL` нет) — иначе
     ❌ `errors.gpu.noDcgm`;
  4. ✅ «Карт: N на хосте <хост>, драйвер <версия>».
- `prometheus`:
  1. «Источник истории подключён» — ❌ с ошибкой источника, если нет;
  2. `count by (hostname, Hostname, instance, gpu) (DCGM_FI_DEV_FB_USED{<селектор>})` — карта, а не экземпляр MIG:
     группировка по `gpu` сводит экземпляры одной карты;
  3. 0 карт — ⚠️ «Источник не собирает метрики DCGM» (с селектором — «под селектором нет карт»); больше 64 —
     ❌ `errors.gpu.tooManyGpus` «Сузьте селектор»; иначе ✅ «Карт: N на хостах: …» (до 20 имён).
  Без селектора — автоподбор (ниже); без единого найденного хоста среди хостов серверов — ⚠️ «Хосты серверов не
  найдены среди карт» и список найденных хостов (до 20) для выбора в форме.
- **Привязка серверов** — шаг на каждый сервер: ✅ «gpu-node-1, все карты (автоподбор)» у сервера без привязки или
  «gpu-node-1, карты 0–3» у сервера с ней; ⚠️ «Хоста сервера нет среди карт — выберите хост вручную»; ⚠️ «Хоста
  привязки нет среди карт» у сохранённой привязки; ⚠️ «Номеров 4, 5 нет на хосте».
- **Сопоставление с историей** (только `direct`, при источнике истории) — шаг на экспортёр: ✅ «`dcgm · host:9400`
  (автоподбор)» или «селектор» (под селектором есть `DCGM_FI_DEV_FB_USED`); ⚠️ «Цели с адресом экспортёра нет»;
  ⚠️ «Под селектором нет серий»; ❌ ошибка разбора селектора.
- **Полнота набора счётчиков** — шаг-подсказка «Счётчики» ⚠️ на каждую группу раздела 4, которой нет ни у одной карты
  (`messages.gpuTest.missingSm`, `missingEcc`, `missingThrottle`, `missingNvlink` — с именами серий). Подключению не
  мешает. Имена новых шагов: `metrics`, `cards`, `bind`, `history`, `counters`.

Сбой компонента GPU не мешает подключению серверов: инсталляция подключена, GPU — ❌ в проверке и ошибка на
вкладке GPU.

**Совпадение хостов** (`gpu/bind.rs`): имена без учёта регистра; короткое имя совпадает с полным, если это его первая
часть (`gpu-node-1` и `gpu-node-1.corp.local` — метка `hostname` обычно короткое имя узла); адреса IP — только
целиком; `localhost`, `127.0.0.1`, `[::1]` — один адрес, как в I1c. DNS проверка не опрашивает.

**Автоподбор селектора `prometheus`.** Хосты серверов — хосты их URL. Совпавшие с хостами карт дают селектор
`{hostname=~"h1|h2"}` — по той метке, которой подписаны найденные карты (`Hostname` у 4.1 и раньше; при картах с
обеими метками берётся `hostname`; без метки хоста — `{instance=~"(h1|h2)(:[0-9]+)?"}`). Значения экранируются для
регулярного выражения.
Срабатывает при проверке, если селектор пуст; подобранный селектор отмечен «автоподбор» в форме.

**Автоподбор привязки** — у серверов без привязки: хост URL сервера совпал с хостом карт → `GpuBinding { host,
indices: None }`. Что привязка подобрана, помнит только форма: подобранную привязку, которую человек изменил, форма
оставляет, а со сменой адреса сервера в той же открытой форме сбрасывает. За балансировщиком и в Kubernetes (URL
указывает на Service) хост не совпадает — привязку выбирает человек.

**Автоподбор `historySelector`** — как селектор сервера в I1c: цель с `instance = host:port` экспортёра среди
`count by (job, instance) (DCGM_FI_DEV_FB_USED)`; несколько `job` — первый по алфавиту, остальные — в списке выбора.

**Ошибки** `errors.gpu.*`: `noHistorySource`, `noDcgm`, `tooManyGpus`, `noExporters`, `tooManyExporters`,
`duplicateExporter`, `badUrl`, `badUsername`, `badBinding`, `unauthorized` (401/403 экспортёра — «проверьте имя
пользователя и пароль», а не ключ API), `notConfigured` (у инсталляции нет компонента), `notMatched` (экспортёры без
селекторов истории), `hostNotInHistory` (в истории нет серий хоста окна), `tooManySeries` (больше 16 карт в окне хоста —
запись `partial`). Сеть —
`errors.server.*`, ответы источника — `errors.history.*`, разбор селекторов — `errors.history.selector` и
`errors.history.selectorName`.

## 4. Rust: модуль `gpu/`

**Канонические поля карты** — `gpu/fields.rs`, таблица кандидатов, чистая функция (имена без префикса `DCGM_FI_`):

| Поле | Серии (по порядку) | Вид | Единица на выходе |
|---|---|---|---|
| `util` | `DEV_GPU_UTIL` | датчик | % |
| `smActive` | `PROF_SM_ACTIVE` → `PROF_GR_ENGINE_ACTIVE` | датчик, доля → % | %, `smSource: sm \| gr` |
| `tensorActive` | `PROF_PIPE_TENSOR_ACTIVE` | датчик, доля → % | % |
| `dramActive` | `PROF_DRAM_ACTIVE` | датчик, доля → % | % |
| `memCopyUtil` | `DEV_MEM_COPY_UTIL` | датчик | % |
| `memUsed`, `memFree`, `memReserved` | `DEV_FB_USED`, `DEV_FB_FREE`, `DEV_FB_RESERVED` | датчики | МиБ; всего = сумма трёх (без `FB_RESERVED` — двух) |
| `temp`, `memTemp` | `DEV_GPU_TEMP`, `DEV_MEMORY_TEMP` | датчики | °C |
| `power` | `DEV_POWER_USAGE` | датчик | Вт |
| `smClock`, `memClock` | `DEV_SM_CLOCK`, `DEV_MEM_CLOCK` | датчики | МГц |
| `throttle` | `DEV_CLOCKS_EVENT_REASONS` → `DEV_CLOCK_THROTTLE_REASONS` | битовая маска | список причин |
| `violation` | `DEV_POWER_VIOLATION`, `DEV_THERMAL_VIOLATION` (нс) | счётчики | доля времени за интервал, % |
| `xid` | `DEV_XID_ERRORS`; `DCGM_EXP_XID_ERRORS_COUNT` при наличии | датчик | код последней (0 — нет), число за окно экспортёра |
| `eccDbe`, `eccSbe` | `DEV_ECC_DBE_VOL_TOTAL`, `DEV_ECC_SBE_VOL_TOTAL` | счётчики | значение и прирост |
| `remapUncorrectable`, `remapCorrectable`, `remapFailure` | `DEV_UNCORRECTABLE_REMAPPED_ROWS`, `DEV_CORRECTABLE_REMAPPED_ROWS`, `DEV_ROW_REMAP_FAILURE` | счётчики, датчик | значение |
| `pcieReplay` | `DEV_PCIE_REPLAY_COUNTER` | счётчик | прирост |
| `pcieTx`, `pcieRx` | `PROF_PCIE_TX_BYTES`, `PROF_PCIE_RX_BYTES` | датчики | Б/с |
| `nvlinkBandwidth` | `DEV_NVLINK_BANDWIDTH_TOTAL` | датчик | МБ/с |
| `nvlinkErrors` | сумма `DEV_NVLINK_CRC_FLIT_ERROR_TOTAL`, `DEV_NVLINK_CRC_DATA_ERROR_TOTAL`, `DEV_NVLINK_REPLAY_ERROR_TOTAL`, `DEV_NVLINK_RECOVERY_ERROR_TOTAL` (до Hopper) или `DEV_NVLINK_CRC_ERROR_TOTAL`, `DEV_NVLINK_RECOVERY_TOTAL`, `DEV_NVLINK_REPLAY_TOTAL` (Hopper) | счётчики | прирост |

Разряды маски троттлинга: `GPU_IDLE` 0x1, `CLOCKS_SETTING` 0x2, `SW_POWER_CAP` 0x4, `HW_SLOWDOWN` 0x8,
`SYNC_BOOST` 0x10, `SW_THERMAL` 0x20, `HW_THERMAL` 0x40, `HW_POWER_BRAKE` 0x80, `DISPLAY_CLOCKS` 0x100. Значками
«троттлинг» на карточке отмечаются `SW_POWER_CAP`, `HW_SLOWDOWN`, `SW_THERMAL`, `HW_THERMAL`, `HW_POWER_BRAKE`;
`GPU_IDLE`, `CLOCKS_SETTING`, `SYNC_BOOST`, `DISPLAY_CLOCKS` — только в подсказке.

Группы для шага «полнота набора»: «активность SM» (нет `PROF_SM_ACTIVE`), «ECC» (нет `DEV_ECC_DBE_VOL_TOTAL`),
«причины троттлинга» (нет ни маски, ни `*_VIOLATION`), «ошибки NVLink» (нет ни одной серии ошибок, а
`NVLINK_BANDWIDTH_TOTAL` > 0).

Метки карты в снимке: `model` (`modelName`), `uuid` (`UUID` или `uuid`), `driver` (`DCGM_FI_DRIVER_VERSION`),
`pciBusId`, `workload { namespace, pod, container }` (при непустых метках Kubernetes). Серии с `GPU_I_ID` полей
карты не дают; карта получает `mig: [{ profile, instance }]`.

**Модули:**

- `gpu/source.rs` — `enum GpuSource { Direct, Prometheus }` с `snapshot()`:
  - `Direct` опрашивает экспортёры через механику `ServerClient` (CA, прокси, таймауты инсталляции, лимит 8 МБ, без
    перенаправлений, basic-вход), не больше 4 запросов одновременно на инсталляцию; разбор — `metrics::parse`.
    Сбой одного экспортёра — запись `errors [{ exporter, error }]`, карты остальных показываются; сбой всех —
    ошибка первого.
  - `Prometheus` — один мгновенный запрос `{__name__=~"DCGM_FI_(DEV|PROF)_(<поля таблицы>)|DCGM_EXP_XID_ERRORS_COUNT",
    <селектор>}` через клиент истории (`history/client.rs`) и общий предел 4 запроса источника (`Source`).
  - Результат: `GpuSnapshot { at, hosts [{ host, driver?, cards [{ index, uuid?, model?, pciBusId?, workload?, mig?,
    exporter?, values { поле → число } }] }], errors [], missing [группы] }`. Больше 64 карт — первые 64 по (хост,
    номер) и `errors.gpu.tooManyGpus` в `errors`.
- `gpu/live.rs` — приросты счётчиков между опросами (`eccDbe`, `eccSbe`, `pcieReplay`, `nvlinkErrors`, доля
  `violation`): снимки за последнюю минуту на инсталляцию в `ServerPool` (как `servers/live.rs`, ключ — инсталляция),
  уменьшение счётчика — «перезапуск», прирост 0. В режиме `prometheus` приросты считает тот же код по мгновенным
  ответам.
- `gpu/bind.rs` — хост карты, автоподбор селектора, привязки и `historySelector`, проверка номеров (раздел 3).
- `gpu/check.rs` — шаги раздела 3.
- `gpu/promql.rs` — шаблоны GPU для окон, чистые функции (отдельно от шаблонов сервера в `history/promql.rs`). Для
  условий `S` (база — селектор `prometheus` или `historySelector` экспортёра, плюс точное условие на метку хоста и
  `gpu="<номер>"` у одной карты, плюс `GPU_I_ID=""` — без экземпляров MIG) и интервала `r` окна (I1c §4), группировка
  `B` = `hostname, Hostname, instance, gpu`:

  | Поле | Шаблон |
  |---|---|
  | Датчик (`util`, `memUsed`, `memFree`, `memReserved`, `temp`, `memTemp`, `power`, `smClock`, `memClock`) | `avg by (B) (avg_over_time(a{S}[r]))` |
  | Доля (`smActive`) | то же, `… or …` по кандидатам, × 100 в Rust |
  | Троттлинг | `max by (B) (max_over_time(a{S}[r])) or …`, причины — разбор маски |
  | Счётчик (`eccDbe`, `pcieReplay`) | `sum by (B) (increase(a{S}[r]))` |
  | Сумма счётчиков (`nvlinkErrors`) | `increase((sum by (B) ({__name__=~"a\|b\|…",S}))[r:r/4])` — подзапрос: `increase` по каждому счётчику убрал бы имя серии, и одинаковые наборы меток столкнулись бы (Prometheus отвечает 422) |

  14 запросов на окно; всего памяти — сумма в Rust. Хост ряда — из меток ответа тем же порядком, что у снимка. Шаги,
  длины и интервалы окон — `Window` и `range` из I1c (интервал опроса цели не запрашивается). Точки без значения — нет
  в `values` точки.
- `gpu/read.rs` — окно истории: сначала `count by (hostname, Hostname, instance) (DCGM_FI_DEV_FB_USED{база})` под
  каждой базой по очереди — какой меткой подписан хост окна (первая база, где он нашёлся); затем шаблоны, не больше 4
  запросов одновременно (общий предел источника), срок окна — как у серверов (I1c §4), частичный сбой — `partial`.
- `gpu/series.rs` — ряды окна: ряд на карту (не больше 16), точка на каждый шаг окна.
- Открытый компонент (клиенты экспортёров или ссылка на источник истории) живёт в пуле подключений
  (`ServerPool::gpu`) до `evict` инсталляции.

**Команды:**

- `check_gpu_source(input)` (профиль формы и секреты: пароль экспортёров и секрет источника истории — по правилам
  сохранения) → `{ report, hosts: [{ host, cards }], available: [host], selector?, bindings: [{ serverId, binding? }],
  exporters: [{ url, historySelector?, targets }] }`; `available` — все хосты карт источника истории (режим
  `prometheus`, для выбора хостов в форме);
- `read_gpu_status(installationId)` → `GpuStatus` — снимок с приростами (`hosts`, `errors`, `missing` и `deltaSec` —
  длина окна приростов в секундах, `null` при первом опросе); фронтенд вызывает раз в 5 с, пока вкладка GPU, «Обзор»
  инсталляции или «Обзор» сервера с привязкой видны;
- `read_gpu_history(installationId, window, host, gpu?)` → `{ window, stepSec, source, series: [{ host, gpu, points:
  [{ at, values }] }], partial: [{ chart, error }] }`, где `source` — вид источника истории; без `gpu` — все карты
  хоста, не больше 16 рядов на график (остальные — `partial` «показаны первые 16 карт»). Без источника истории —
  `errors.history.noSource`; если ни у одного экспортёра нет `historySelector` — `errors.gpu.notMatched`.

Ответы не пишутся на диск; пароль экспортёров не попадает в логи и ошибки.

## 5. Интерфейс

**Форма инсталляции** — раздел «GPU (DCGM)» после «Истории метрик», всегда на виде (`GpuFields.tsx` по образцу
`HistoryFields`):

- переключатель «Нет / Экспортёры DCGM / Из источника истории»; третий вариант неактивен без источника истории, с
  подсказкой «Добавьте источник истории»;
- «Экспортёры DCGM»: список адресов (добавить или удалить, до 16); вход «без входа / логин и пароль» с правилами
  подсказки и флажка удаления секрета, как у истории; CA, прокси, проверка сертификата; у каждого экспортёра
  свёрнутое поле «Серии в истории» — найденные цели, «Свой селектор…», «Не сопоставлять» (как у серверов в I1c);
- «Из источника истории»: поле «Селектор карт» и после проверки — флажки найденных хостов (до 20), которые собирают
  селектор `hostname=~"…"` (или `instance=~"(…)(:[0-9]+)?"`, если у карт нет метки хоста); отметка «автоподбор».
  Селектор другого вида, записанный вручную, флажки не понимают: они неактивны, под ними подсказка
  `installations.gpu.hostsByHand` «Селектор записан вручную: очистите его, чтобы выбирать хосты флажками»;
- кнопка «Проверить GPU» — шаги раздела 3; форма с сохранённым компонентом запускает проверку сама при открытии.

**Форма сервера** — поле «GPU»: «Нет» или хост из найденных проверкой; при выбранном хосте — «Все карты» или флажки
номеров. Подобранную проверкой привязку можно изменить вручную — она остаётся. До проверки — подсказка «Найденные
хосты появятся после «Проверить GPU»»; сохранённая привязка к хосту, которого нет среди найденных, — своим пунктом с
пометкой «не найден». Без компонента GPU поля нет.

**Дерево:** у инсталляции с компонентом GPU — узел «GPU» с числом карт; открывает вкладку GPU.

**Вкладка GPU** (`components/gpu/`):

- сверху — переключатель «Сейчас / 1 ч / 24 ч / 7 д / 30 д» (тот же компонент, что на вкладке «Метрики»), строка
  ошибок экспортёров, подсказка о неполном наборе счётчиков со ссылкой на главу справки;
- группы по хостам: имя, драйвер, число карт, привязанные серверы → карточки карт: номер и модель; полосы
  «Утилизация», «SM» (с пометкой «по GR engine», если запасной источник), «Память X / Y ГиБ»; температура, мощность;
  значки ⚠️ троттлинга, XID, ECC, NVLink/PCIe с подсказкой-расшифровкой; значки ECC взаимоисключающие: некорректируемые
  ошибки — «ECC: N», иначе сбой переназначения строк — «ECC: сбой переназначения», иначе рост корректируемых —
  «ECC +N»; «Нагрузка: namespace/pod» в Kubernetes;
  «MIG: профили» у карт с экземплярами; поле без данных — «нет данных»;
- щелчок по карточке или заголовку хоста раскрывает графики под группой: «Утилизация и SM», «Память», «Температура»,
  «Мощность», «Такты»; для хоста — ряд на карту (до 16), легенда по номерам;
- окно «Сейчас» — буфер в хуке `useGpuStatus` (до 1 ч, по ряду на карту), как `useServerMetrics`; при открытии
  вкладки с доступной историей буфер предзаполняется окном `now` (15 минут), граница «История до HH:MM» — как в I1c;
- окна истории без источника или без сопоставления неактивны с подсказкой, как у серверов; ошибка и `partial` —
  как в I1c.

**Обзор инсталляции:** блок «GPU по хостам» — строка на хост: модель (или «разные»), число карт, средняя
утилизация, память (сумма занятой / всего), максимальная температура, значки проблем; щелчок открывает вкладку
GPU. Ошибка компонента — одна строка с причиной.

**Обзор сервера:** блок «GPU сервера» — строка на привязанную карту (номер, утилизация, память, температура,
значки) и ссылка «Открыть GPU». Без привязки при компоненте GPU — одна подсказка «Привяжите GPU в форме сервера»;
без компонента блока нет.

**Тексты и справка.** Все тексты — в словарях en и ru. Новая глава `gpu` (en, ru): режимы и когда какой выбрать,
пример `scrape_configs` для dcgm-exporter, привязка серверов, какие счётчики включить в файле счётчиков
dcgm-exporter (`DCGM_FI_PROF_SM_ACTIVE`, `DCGM_FI_DEV_ECC_*_VOL_TOTAL`, `DCGM_FI_DEV_CLOCKS_EVENT_REASONS`, ошибки
NVLink), MIG, что значат значки. Подсказки к полям формы; глава «Серверы» и `getting-started` — ссылка на главу
`gpu`.

## 7. Риски этапа

| Риск | Мера |
|---|---|
| Формат мока отличается от настоящего экспортёра (метки, единицы, версии 4.1/4.8) | Снимки по исходникам 4.8.4, кандидаты меток `hostname`/`Hostname`, `UUID`/`uuid`; сверка формата — первый пункт смоука на стенде |
| Набор по умолчанию без SM, ECC и троттлинга — экран и будущие правила `gpu.*` без данных | Запасные серии, «нет данных» вместо нуля, шаг «полнота набора» с перечнем счётчиков, глава справки |
| Хост URL сервера не совпадает с хостом карт (балансировщик, Service Kubernetes) | Ручная привязка в форме сервера; ⚠️ в проверке; точные связи — I3 |
| Корпоративный Prometheus собирает сотни карт | Селектор с автоподбором, предел 64 карты, ❌ «Сузьте селектор» |
| `XID_ERRORS` — код последней ошибки, а не счётчик: старая ошибка висит до перезагрузки драйвера | В подсказке — «последняя XID-ошибка»; число за окно — из `DCGM_EXP_XID_ERRORS_COUNT`, если включён; правило `gpu.xid` в I2 смотрит на смену значения за окно |
| MIG меняет набор серий | Экземпляры MIG только перечисляются; метрики экземпляров — после MVP |

## 8. Изменения общей спеки

Внесены в общую спеку последней задачей плана I1d.

- §5.3 «GPU»: компонент — раздел 2 этой спеки (`direct` — до 16 экспортёров с общим входом basic, `prometheus` —
  селектор карт с автоподбором, не больше 64 карт); хост карты — метка `hostname` (dcgm-exporter 4.8) или
  `Hostname` (4.1 и раньше), иначе адрес экспортёра.
- §5.7: до I3 привязка сервера к GPU — `ServerConfig.gpus` (раздел 2); в I3 она становится частью `bindings`.
- §5.8: шаги проверки DCGM — раздел 3; признак экспортёра — `DCGM_FI_DEV_FB_USED` вместо `DCGM_FI_DEV_GPU_UTIL`
  (в режиме MIG утилизации карты нет).
- §6.2 и §6.3: блоки «GPU по хостам» и «GPU сервера» — раздел 5.
- §6.4: активность SM — `DCGM_FI_PROF_SM_ACTIVE`, без неё `DCGM_FI_PROF_GR_ENGINE_ACTIVE` с пометкой; до I3 вместо
  процессов — «Нагрузка» по меткам Kubernetes экспортёра; MIG — только перечень экземпляров.
- §7.2: `gpu.idleWithQueue` берёт активность SM с тем же запасом; `gpu.throttling` и `gpu.eccUncorrectable` без
  нужных счётчиков — «не хватает данных» с названием счётчика (§7.1, `check.partial`).
- §20: строка I1d — «DCGM (`direct`, `prometheus`), привязка карт к хостам и серверам, экран GPU, блоки GPU в
  обзорах инсталляции и сервера».
