# Glafira for LLM Inference — спека этапа I1c «История метрик»

Уточнения поверх общей спеки `docs/superpowers/specs/2026-10-29-glafira-inference-design.md` (дальше — «общая
спека») и спеки I1b `docs/superpowers/specs/2026-10-31-glafira-inference-i1b-design.md`. Где эта спека молчит,
действуют они. Решения брейншторма 2026-10-31.

## 1. Решения и границы

- **Этап I1c «История и GPU» делится на два.** I1c «История метрик» — источник Prometheus/VictoriaMetrics,
  сопоставление серий с серверами, окна 1 ч / 24 ч / 7 д / 30 д, окно «Сейчас» из истории. I1d «GPU» — DCGM
  (`direct`, `prometheus`), привязка карт к хостам, экран GPU; режим `prometheus` берёт клиент истории из I1c. Строка
  I1c в §20 общей спеки заменяется двумя (раздел 9).
- **Проверка — на настоящем Prometheus.** Владелец ставит Prometheus локально (`brew install prometheus`), конфиг
  смоука опрашивает моки vLLM и SGLang; с него снимаются ответы API для тестов. Мок источника в `mock-server.mjs` —
  только для отказов. VictoriaMetrics и GPU-стенд — по желанию, когда появятся.
- **Сопоставление — найденные цели плюс автоподбор** (раздел 3).
- **PromQL собирает Rust** (подход A): шаблоны — чистые функции над картой метрик адаптера, одна команда на окно;
  интерфейс произвольных запросов к источнику не делает. Те же шаблоны в I2 питают MCP `get_metrics_history`.
- **История показывается** в окнах 1 ч / 24 ч / 7 д / 30 д вкладки «Метрики» и предзаполняет окно «Сейчас»
  последними 15 минутами.
- **Не входит в I1c:** DCGM и экран GPU (I1d); история в «Обзоре» инсталляции (§6.2 общей спеки — с I2); правила,
  которым нужна история, и разрыв `noHistory` (I2); MCP `get_metrics_history` (I2).

## 2. Профиль и секреты

- `InstallationProfile.history: Option<HistorySource>` — не больше одного источника на инсталляцию:

  ```
  HistorySource { url, auth: none | bearer | basic { username }, ca: CaConfig, proxy: ProxyConfig,
                  insecure_skip_tls_verify: bool }
  ```

  `insecure_skip_tls_verify` — как у серверов: постоянное предупреждение, запрещается политикой
  `allowInsecureTls = false`. Тип источника (Prometheus или VictoriaMetrics) определяет проверка и только показывает.
- `ServerConfig.history_selector: Option<String>` — селектор серий сервера, `{job="vllm", instance="10.0.0.5:8000"}`.
  Заполняет автоподбор или человек; `None` — история сервера недоступна.
- Токен (bearer) и пароль (basic) — только в keychain: `secret_key(installationId, "history", "token" | "password")`.
  Удаление источника удаляет секрет.
- Экспорт и импорт — как в семействе: секрета в файле нет, у инсталляции флаг `needsSecret.history`; при обновлении
  импорт предупреждает, если у источника с сохранённым секретом меняются адрес, прокси или проверка сертификата
  (секрет уйдёт на новый адрес). Селекторы серверов экспортируются как есть.

## 3. Проверка источника и сопоставление

**Шаги проверки** (§5.8 общей спеки, уточнение):

1. DNS/TCP → TLS — как у серверов.
2. Вход — `GET /api/v1/status/buildinfo`. 401/403 — ❌ «Источник требует вход» или «Вход отклонён»; 404 — шаг
   пропущен (вход проверит следующий запрос); версия из ответа — в подпись источника.
3. Запрос `up` — `GET /api/v1/query?query=up`; `status != success` — ❌ с текстом ошибки источника (до 512 символов).
4. Цели инференса — `count by (job, instance) ({__name__=~"vllm:.+|sglang:.+"})`: ✅ «Найдены цели инференса: N»,
   0 — ⚠️ «Источник не собирает метрики vLLM и SGLang». Тип цели — по второму запросу
   `count by (job, instance) ({__name__=~"sglang:.+"})`: цели из него — SGLang, остальные — vLLM.
5. Сопоставление — шаг на каждый сервер: ✅ «`vllm · 10.0.0.5:8000` (автоподбор)» или «(выбрано)»; ⚠️ «Цель не
   найдена — выберите вручную»; ⚠️ «Под селектором нет серий»; ❌ «Селектор не разобран: …».

Сбой источника не мешает подключению серверов: инсталляция подключена, история — ❌ в проверке и «История недоступна»
у окон.

**Автоподбор.** Цель подходит серверу, если `instance` равен `host:port` его адреса: схема и путь не учитываются,
`localhost`, `127.0.0.1` и `[::1]` — один адрес, порт по умолчанию — из схемы (80 / 443). Одна подходящая цель —
селектор `{job="<job>", instance="<instance>"}`; несколько (одна цель в нескольких `job`) — первая по `job` в
алфавитном порядке, остальные — в списке выбора. Автоподбор срабатывает при проверке у серверов без селектора и при
смене адреса сервера, выбор человека не перезаписывает.

**Ручной селектор.** Строгий разбор: `{` метки `}`, матчеры `=`, `!=`, `=~`, `!~`, значения в двойных кавычках с
экранированием `\"` и `\\`, хотя бы один матчер, `__name__` запрещён (имя серии подставляет шаблон). Иначе —
`errors.history.selector` с позицией.

**Ошибки источника** — ключи `errors.history.*`: `unreachable`, `unauthorized`, `forbidden`, `timeout`, `badData`
(текст источника до 512 символов), `tooManyPoints`, `tooLarge` (ответ больше 8 МБ), `unexpected` (не JSON или
неизвестный `resultType`).

## 4. Rust: модуль `history/`

- `history/client.rs` — клиент источника поверх механики `ServerClient` (CA, прокси, таймауты инсталляции, лимит
  ответа 8 МБ, без перенаправлений): `buildinfo`, `query`, `query_range`, `targets` (`/api/v1/targets?state=active` —
  `scrapeInterval` цели; нет эндпоинта — `None`). Разбор `vector` и `matrix`; значения `"NaN"`, `"+Inf"`, `"-Inf"` —
  отсутствие значения в точке.
- `history/promql.rs` — шаблоны, чистые функции над `MetricSpec` адаптера (кандидаты имён, вид серии, `matches`
  как матчеры меток). Для селектора `S` (матчеры без фигурных скобок) и интервала `r`, кандидаты `a`, `b`:

  | Метрика | Шаблон |
  |---|---|
  | Датчик (running, waiting) | `sum(a{S}) or sum(b{S})` |
  | KV-кэш | `max(a{S}) or max(b{S})` и `avg(a{S}) or avg(b{S})` |
  | Скорость счётчика (токены, вытеснения, прерванные) | `sum(rate(a{S}[r])) or sum(rate(b{S}[r]))` |
  | Завершения по причинам | `sum by (finished_reason) (rate(a{S}[r]))` (метка — как в карте адаптера) |
  | Prefix-cache | `(sum(rate(hits{S}[r])) or …) / (sum(rate(queries{S}[r])) or …)` |
  | Перцентиль | `histogram_quantile(q, sum by (le) (rate(a_bucket{S}[r])) or sum by (le) (rate(b_bucket{S}[r])))` |

  Перцентили: p50, p95, p99 для TTFT, ITL, E2E; p95 для времени в очереди. Около 20 запросов на окно. Секунды
  гистограмм переводятся в миллисекунды в Rust, как в I1b. Перезапуски обрабатывает `rate`; точки без значения —
  `null`, на графике разрыв.
- `history/window.rs` — окна, шаги, интервалы:

  | Окно | Длина | Шаг | Точек |
  |---|---|---|---|
  | `now` (предзаполнение) | 15 мин | 15 с | 60 |
  | `1h` | 1 ч | 60 с | 60 |
  | `24h` | 24 ч | 90 с | 960 |
  | `7d` | 7 д | 12 мин | 840 |
  | `30d` | 30 д | 45 мин | 960 |

  Интервал `r = max(шаг, 4 × scrapeInterval)`, без `scrapeInterval` — `max(шаг, 1 мин)`. Конец окна — `now`,
  округлённый вниз до шага (повторные запросы окна попадают в кеш источника).
- `history/targets.rs` — поиск целей, автоподбор (раздел 3), разбор и сборка селектора.
- `history/series.rs` — сборка точек: матрицы запросов выравниваются по меткам времени окна, точка — `ServerMetrics`
  той же формы, что в окне «Сейчас» (`gauges`, `rates`, `prefixCacheHitRatio`, `latency`, `latency1m = latency`,
  `missing` — метрики без единого значения в окне, `series` — кандидат, давший ряд, если его можно определить;
  `reset` всегда `false`, `engines` — 0: число движков знает только живой опрос, «Обзор» без него строку «Движки»
  не показывает).

**Команды:**

- `check_history_source(installationId | draft)` — шаги раздела 3 для формы и проверки инсталляции;
- `discover_history_targets(draft)` — цели и автоподбор для формы;
- `read_server_history(installationId, serverId, window)` →
  `{ window, stepSec, source: "prometheus" | "victoriametrics", points: [{ at, m }], partial: [{ chart, error }] }`.

Не больше 4 запросов к источнику одновременно на инсталляцию. Сбой одного запроса — `null` в его ряду и запись в
`partial`; окно целиком падает, только если упали все запросы (ошибка первого). Ответы не кешируются в Glafira и
не пишутся на диск; токен источника не попадает в логи и ошибки.

## 5. Интерфейс

**Вкладка «Метрики».**

- Окна «1 ч», «24 ч», «7 д», «30 д» доступны, если у инсталляции есть источник, а у сервера — селектор. Иначе
  неактивны с подсказкой: «Добавьте источник истории в инсталляцию» или «Серии сервера не сопоставлены с историей».
- Окно — `useQuery(["serverHistory", installationId, serverId, window])`, `staleTime` 1 мин; загрузка — прежние
  графики под полупрозрачным слоем; кнопка «Обновить» перезапрашивает. Автоматического перезапроса окна истории нет;
  «Обзор» и строка «Сейчас» на карточке продолжают опрос `/metrics`, пока вкладка видна.
- Над графиками — «Шаг 90 с · Prometheus»; частичное окно — «Часть рядов не прочитана: <график> — <ошибка>»; ошибка
  окна — текст ошибки вместо графиков. Ось времени окон 7 д и 30 д — с датами.

**Окно «Сейчас» из истории.** При первом открытии вкладки сервера с историей `useServerMetrics` один раз запрашивает
окно `now` и кладёт точки в начало буфера; опрос `/metrics` дописывает после них. Граница — вертикальная пунктирная
линия с подписью «История до HH:MM». Сбой запроса — окно ведёт себя как в I1b, причина — в подсказке переключателя
окон. Плитки «Обзора» до второго живого опроса показывают последнюю точку истории (TTFT и ITL «за минуту» — из
неё), с подсказкой «по истории».

**Форма инсталляции.** Раздел «История метрик (Prometheus / VictoriaMetrics)», по умолчанию свёрнут: адрес,
авторизация (без неё / токен / логин и пароль), CA, прокси, проверка сертификата; кнопка «Проверить источник»
(шаги раздела 3). После проверки у каждого сервера — поле «Серии в истории»: список найденных целей
`job · instance (vLLM | SGLang)`, «Свой селектор…» (поле ввода с разбором на лету), «Не сопоставлять»; отметка
«автоподбор» у подобранной цели.

**Карточка сервера** во вкладке инсталляции — строка «История»: `job · instance` или «не сопоставлена»; без
источника строки нет.

**Тексты и справка.** Все тексты — в словарях en и ru. Новая глава «История метрик» (en, ru): подключение источника,
пример `scrape_configs` для vLLM и SGLang, сопоставление и что делать, если не сопоставилось, окна и шаги, частичные
окна. Глава «Серверы» — ссылка на неё в разделе о метриках. README и `getting-started` — строка про историю.

## 6. Тестирование

- **Снимки настоящего Prometheus:** конфиг `scripts/prometheus/smoke.yml` (опрос моков `vllm` :8000,
  `vllm --engines 2` :8001, `sglang` :30000, `vllm --reset-after 20` :8003 раз в 5 с; по желанию настоящий vLLM на
  `vllm-metal` :8100). После 15–20 минут сбора снимаются ответы `buildinfo`, `targets`, `up`, поиска целей,
  `query_range` каждого шаблона, ошибка `bad_data`, пустой результат — в
  `src-tauri/src/history/testdata/prometheus-<версия>/` с файлом `README.md` (как сняты).
- **Rust (чистые):** точный текст шаблона для каждой метрики vLLM и SGLang, `or` по кандидатам, `matches` как
  матчеры, экранирование значений; шаги и интервалы окон; автоподбор (`localhost`, порты по умолчанию, несколько
  `job`); разбор селектора (правильные и неправильные, позиция ошибки); сборка точек из снятых матриц (выравнивание,
  `NaN` и `+Inf`, ряд без значений → `missing`, частичный сбой → `partial`); ошибки клиента на моке.
- **Мок источника:** вид `prometheus` в `mock-server.mjs` отдаёт снятые снимки и умеет отказывать: `--token`
  (401 без него), `--slow` (таймаут), `bad_data` на селектор с `__bad__`, `--huge` (ответ больше 8 МБ). Тесты скриптов
  — на каждый отказ.
- **Фронтенд:** доступность окон и подсказки, загрузка и `partial`, предзаполнение буфера и граница «История до…»,
  поле «Серии в истории» (автоподбор, выбор, свой селектор, ошибка разбора), строка «История» на карточке.
- **Смоук `docs/smoke/i1c.md`:** подключение и проверка источника; автоподбор, ручной выбор цели для `--engines 2`,
  свой селектор и его ошибка; окна 1 ч…30 д (короткие заполнены, длинные — за время жизни Prometheus), сверка точки
  с веб-интерфейсом Prometheus по тому же запросу; «Сейчас» заполнено при открытии; перезапуск мока без всплеска в
  `rate`; Prometheus остановлен — «Сейчас» работает, окна истории — ошибка, инсталляция подключена; токен через мок
  `prometheus` — секрета нет на диске и в логах; справка и английский.

## 7. Риски этапа

| Риск | Мера |
|---|---|
| `instance` не совпадает с адресом сервера (Kubernetes, балансировщик) | Список найденных целей и ручной выбор; ⚠️ в проверке |
| `or` по кандидатам смешивает два имени в одной точке (обе серии есть в 0.10.x–0.11.x) | `or` берёт левую часть, где она есть — тот же порядок кандидатов, что в I1b |
| Тяжёлые запросы за 30 дней на большом Prometheus | Не больше 4 одновременно, шаг 45 мин, таймаут инсталляции, кнопка «Обновить» вместо автоперезапроса |
| VictoriaMetrics отличается от Prometheus (MetricsQL, `targets`) | Только совместимые функции; без `targets` — интервал по умолчанию; смоук VM по желанию |
| Мок растит счётчики за опрос, а не за секунду | Скорости в смоуке сверяются с веб-интерфейсом Prometheus, а не с ожиданием «настоящих» чисел |

## 8. Риски, перенесённые из I1b

- Сумма серий SGLang по `tp_rank` — проверить на стенде (касается и шаблонов `sum`).
- Буфер точек «Сейчас» у каждого экземпляра хука — предзаполнение из истории делает это заметнее (две вкладки
  одного сервера запрашивают окно `now` дважды); общий буфер — при необходимости.
